`hello-world` is a small reference skill that ships with `arc-skill-eval`. A run of its suite exercises discovery, execution, grading, workspace capture, and artifact writing. If its evals pass, those stages work.

The skill lives in the repo at [`skills/hello-world/`](https://github.com/andysolomon/arc-skill-eval/tree/main/skills/hello-world).

## What `SKILL.md` says

The skill is deliberately trivial. From its `SKILL.md`:

> When invoked, follow these steps exactly:
>
> 1. Read the prompt and extract the intended greeter name.
>    - If the prompt names a specific recipient ("a greeting for Ada", "greet Grace"), use that name verbatim.
>    - If the prompt is generic ("create a greeting"), use `world`.
> 2. Use the **Write** tool to create a file called **`greeting.txt`** in the workspace root. The file content is exactly one line: `Hello, <name>!` (note the comma, the space after it, and the trailing exclamation mark).
> 3. Reply with a **single sentence** that confirms the file was written and mentions the filename `greeting.txt` explicitly.

Two details make the skill easy to grade:

- The file has one line with exact punctuation, so a regex can check it. A model can paraphrase intent, but it can't paraphrase punctuation.
- The reply must contain the literal string `greeting.txt`, so a regex can check the reply too.

## What `evals/evals.json` checks

The suite has three cases. This is the file as it ships:

```json
{
  "skill_name": "hello-world",
  "evals": [
    {
      "id": "default-world",
      "prompt": "Create a greeting.",
      "expected_output": "greeting.txt exists in the workspace with 'Hello, world!' and the assistant reply names the file.",
      "assertions": [
        { "type": "file-exists", "path": "greeting.txt" },
        { "type": "regex-match", "pattern": "Hello, world!", "target": { "file": "greeting.txt" } },
        { "type": "regex-match", "pattern": "greeting\\.txt", "target": "assistant-text" }
      ]
    },
    {
      "id": "named-ada",
      "prompt": "Create a greeting for Ada.",
      "expected_output": "greeting.txt contains 'Hello, Ada!' and the assistant reply names the file.",
      "assertions": [
        { "type": "file-exists", "path": "greeting.txt" },
        { "type": "regex-match", "pattern": "Hello, Ada!", "target": { "file": "greeting.txt" } },
        { "type": "regex-match", "pattern": "greeting\\.txt", "target": "assistant-text" }
      ]
    },
    {
      "id": "assistant-names-file",
      "prompt": "Please generate a greeting for Grace Hopper.",
      "expected_output": "greeting.txt exists; assistant text mentions 'greeting.txt' literally.",
      "assertions": [
        { "type": "file-exists", "path": "greeting.txt" },
        { "type": "regex-match", "pattern": "greeting\\.txt", "target": "assistant-text" },
        { "type": "regex-match", "pattern": "Hello, Grace Hopper!", "target": { "file": "greeting.txt" } }
      ]
    }
  ]
}
```

Points to notice:

- **Every assertion is deterministic.** Each case checks that the file exists, that the file body matches, and that the reply names the file. No judge model is involved, so the suite gives the same verdict for the same output every time and costs nothing to grade.
- **`target: "assistant-text"`** points `regex-match` at the assistant's reply instead of a workspace file. The same assertion type checks both.
- **`Hello, Grace Hopper!`** in the third case checks that a two-word name comes through intact. If the skill mangles the name, the regex fails.
- **No `setup` and no `files`.** Every case starts from an empty workspace. Hello-world tests one skill's effect on an empty directory, not repo state.

Earlier versions of the suite used judge assertions for the reply. Regex checks on `assistant-text` replaced them to keep the smoke test deterministic. Real skills usually need a judge for prose claims. See [Assertions](/arc-skill-eval/concepts/assertions/) for when to use one.

## Run it

```bash
arc-skill-eval run ./skills/hello-world
```

Stdout shows one line per case, `PASS` or `FAIL` with the case ID, then a summary. Model latency accounts for most of the wall-clock time.

## Read the artifacts

After a clean run, you have:

```text
skills/hello-world/evals-runs/<runId>/
├── eval-default-world/
│   ├── assistant.md          # "I wrote greeting.txt with the greeting."
│   ├── outputs/greeting.txt  # "Hello, world!"
│   ├── timing.json
│   ├── grading.json          # 3 assertions, all passed
│   ├── trace.json
│   ├── tool-summary.json     # tool_calls_by_name: { write: 1 }
│   └── context-manifest.json # only attached skill: hello-world
├── eval-named-ada/
│   └── ...
└── eval-assistant-names-file/
    └── ...
```

Check three things after a successful run:

1. **`grading.json` has `summary.pass_rate` of `1`** for each case. A lower value means an assertion failed.
2. **`tool-summary.json` has `tool_calls_by_name`** with `write: 1` and nothing else. If the skill ran `bash`, it broke the `SKILL.md` rule "Do not run shell commands."
3. **`context-manifest.json` has one entry in `attached_skills`**: `hello-world` with role `target`. Any other entry means an ambient skill leaked into the context.

## Compare against the no-skill baseline

```bash
arc-skill-eval run ./skills/hello-world --compare
```

Compare mode shows whether the skill instructions change the result. With the skill attached, current Claude and GPT models usually pass all three cases. Without it, the model often picks a different filename or misses the exact punctuation. The `benchmark.json` delta records the difference in pass rates.

## Use it as a template

To write evals for your first skill, copy this directory and edit it:

1. `SKILL.md`: replace the steps with your skill's logic. Keep at least one detail the model can't paraphrase, such as a literal filename, a specific word, or an exact format.
2. `evals/evals.json`: replace the cases. Aim for six to ten. Use script assertions first and add judge assertions only for prose.
3. `evals/files/<fixture>/` *(optional)*: add fixtures for cases that need existing repo state. Hello-world has none.

For more guidance, see [Authoring evals](/arc-skill-eval/authoring-evals/).
