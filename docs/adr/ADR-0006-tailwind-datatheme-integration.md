# ADR-0006: Tailwind v4 + `[data-theme]` integration pattern

## Status

Accepted (2026-07-22)

## Context

Issue #166 asks which Tailwind major version and which integration pattern
(`@theme` directive, theme config object, or `@plugin`) makes
`[data-theme="tokyonight|gruvbox|nord"]` swap cleanly without layout shift,
while still allowing raw token access for non-utility usages (inline-glyph
colors in the prototype that escape utility classes).

Prior ADRs already constrain the answer space:

- **ADR-0002** — Web stack is Vite + React + TS; styling is Tailwind with
  `@theme`-mapped tokens and `[data-theme]` on `<html>`.
- **ADR-0003 / ADR-0005** — `@arc-skill-eval/tokens` is the single source of
  truth; the web surface consumes a generated Tailwind v4 `@theme` CSS
  artifact (`dist/web-theme.css`), not a runtime Tailwind plugin and not the
  TypeScript palettes in the browser bundle.

The generator (`packages/tokens/tailwind-theme.css.template` →
`packages/tokens/dist/web-theme.css`) already emits:

- an `@theme { … }` block with `--tt-*` / `--color-tt-*` custom properties
- `:root` / `[data-theme="<default>"]` role aliases
- per-theme `[data-theme="<name>"]` blocks that retarget the role aliases

What remained open was the **consumer-side wiring**: exact Tailwind major,
exact import statement, and a concrete `app.css` shape section specs can cite
without re-litigating the pattern.

Every visual section ticket (#170–#175) is blocked on this pin.

## Decision

**Tailwind v4 + import generated `@arc-skill-eval/tokens` `web-theme.css` +
`data-theme` attribute aliases on `<html>`.** Reject theme-config-object and
`@plugin` integration paths for the web app.

### 1. Tailwind major version

- **Pinned:** Tailwind **v4**.
- **Rationale:** The tokens package already generates Tailwind v4 `@theme`
  syntax (ADR-0002 / ADR-0005). A v3 theme-config object would require a
  second generator shape and duplicate the contract.
- **Rejected:** Tailwind v3 `theme.extend` config object — wrong major for the
  generated artifact.
- **Rejected:** Tailwind `@plugin` entrypoint from the tokens package —
  ADR-0005 already rejected shipping a plugin; the web app consumes CSS.

### 2. Integration pattern

Import the generated CSS artifact into the web app's global stylesheet. Theme
swap is an attribute change on `<html>`, not a remount and not a Tailwind
rebuild:

```html
<html data-theme="tokyonight">
```

Valid values: `tokyonight` | `gruvbox` | `nord` (default `tokyonight` per
tokens package). Changing `data-theme` retargets the `--tt-*` role aliases via
the selectors already emitted in `web-theme.css`.

### 3. Exact import + recommended `app.css` shape

Consumer entry CSS (illustrative path `web/src/app.css`; exact file location
is a downstream wiring concern):

```css
@import "tailwindcss";
@import "@arc-skill-eval/tokens/web-theme.css";

/* Optional app-local layers below — do not redefine --tt-* roles here. */
```

- First line pulls Tailwind v4.
- Second line pulls the generated `@theme` block and `[data-theme]` alias
  maps from `@arc-skill-eval/tokens`.
- Components use Tailwind utilities mapped from the `@theme` tokens (e.g.
  `bg-tt-bg`, `text-tt-fg`, `text-tt-blue`) **or** raw custom properties.

Package export note: consumers resolve
`@arc-skill-eval/tokens/web-theme.css` to the generated
`packages/tokens/dist/web-theme.css` (regenerated by the tokens `build` /
web `predev` / `prebuild` hooks per ADR-0005). Wiring that export path is
part of the downstream web-app slice, not this ADR.

### 4. Raw `--tt-*` access remains first-class

The generated CSS keeps semantic roles as CSS custom properties
(`--tt-bg`, `--tt-fg`, `--tt-blue`, `--tt-comment`, …). Prototype-style
inline usages that escape utility classes remain valid:

```tsx
<span style={{ color: "var(--tt-magenta)" }} />
```

Utilities and raw vars read the same role aliases, so a `data-theme` swap
updates both without remount or layout shift from theme-specific trees.

### 5. Out of scope (downstream)

This ADR pins the pattern only. It does **not** scaffold `web/`, install
Tailwind, or edit `packages/tokens` exports / `tokens.ts`. Those are later
slices unblocked by closing #166.

## Consequences

- **Positive** — Section specs (#170–#175) can cite one import + one
  `data-theme` convention instead of choosing among `@theme` / config /
  `@plugin` per PR.
- **Positive** — Aligns with **ADR-0002** (stack: Vite/React/Tailwind +
  `[data-theme]`) and **ADR-0005** (package contract: generated
  `web-theme.css`, not a plugin).
- **Positive** — Raw `--tt-*` vars stay available for escape-hatch inline
  glyphs without a parallel hex table.
- **Negative** — Locked to Tailwind v4 `@theme` shape; a future major bump
  that changes directive syntax is a template + ADR follow-up (already noted
  in ADR-0002).
- **Neutral** — Actual `web/` CSS file and package `exports["./web-theme.css"]`
  wiring remain implementation work; this document is the contract those
  tickets implement.
